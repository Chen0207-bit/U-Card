# 优卡 U-Card 业务系统 Demo

基于《优卡 U-Card 业务系统 PRD v1.0》的演示版：虚拟支付卡 + 多级分销 CRM + 积分商城，前后端完整业务闭环。

## 访问

- **线上**：后台 https://fc-ucard.feng85656.workers.dev/ ｜ 用户端 https://fc-ucard.feng85656.workers.dev/app ｜ 商户端 https://fc-ucard.feng85656.workers.dev/merchant
- **本地**：`node server.js` → http://localhost:5177/、/app、/merchant、/data-console（零依赖，Node ≥ 14）
- **源码**：https://github.com/Chen0207-bit/U-Card（按功能拆分 commit）

内存数据库 + 确定性种子数据（12 持卡人 / 12 卡 / 30 天交易 / 18 CRM 客户 / 10 商品 / 19 人销售组织），重启即还原。

## 三端视角（演示动线）

### 用户端 `/app`（持卡人）
选账号登录 → 卡包（卡号掩码/3D 卡面）→ USDT/法币充值 → 消费（积分抵扣+返积分）→ 任务签到 → 商城兑换（核销码）→ KYC 升级 → 邀请推广

### 后台 `/`（按身份登录，demo 免密选账号）
- **销售总监**：全局驾驶舱 + 所有模块 + **分销链路全景**（组织树/每笔交易分佣流向）
- **一级/二级销售**：自己的驾驶舱/客户/业绩/佣金 + 自己团队的分销链路
- **三级销售**：只看自己的客户/业绩/佣金
- 数据范围 = 本人 + 全部下级子树（PRD 模块1 "数据权限：全部/本部门/本人" 的落地）

## 多级分销佣金（核心演示点）

组织结构：销售总监 → 一级销售×2 → 每人二级×2 → 每人三级×3（共 18 销售 + 1 总监）

每笔充值/消费实时沿链路生成佣金（比例配置在 `core.js` 的 `COMMISSION`）：

```
客户消费 $100
  → 三级销售(直属)   +$1.00 (1%)
  → 二级销售(上级)   +$2.00 (2%)
  → 一级销售(上上级) +$0.50 (0.5%)
```

后台「分销链路」页：分佣规则卡 + 销售组织树（各级直属/分润佣金）+ 最近 10 笔交易的实时分佣链路流向图。**此页与驾驶舱已开启自动监听（5 秒轮询）**——在用户端发起一笔消费，新链路数秒内自动出现、高亮并弹出 toast，无需手动刷新。

安全（演示级）：总监专属操作（退款/KYC 审核/佣金结算/积分发放/发货/上下架/冻结调账）在服务端校验身份，销售身份调用返回 403。

## 2.0 新增运营能力

- **驾驶舱**：今日/本周/本月/本季时间范围切换，9 张可点击指标卡（GMV/充值/消费/活跃用户/卡量/待审 KYC/待发货/待结算佣金/风险交易），趋势图按范围自适应粒度，业绩榜行点击看销售详情
- **分销链路明细**：每笔交易的逐级佣金表（层级/比例/金额/结算状态/关联单号+合计），固定演示流程卡
- **风控模拟中心**：风险事件（15 条种子 + 处置动作 + 事件时间轴）、5 条模拟规则（可启停）、黑白名单、风险标签；处置「解除风控」联动解冻卡片
- **财务对账中心**：充值/消费/退款按天对账（应入账/实际入账/差异/凭证号）、差异清单、商户结算（可标记已结算）、月度财务报表（净收入=手续费+卡月费−佣金）+ CSV 导出
- **演示数据重置**：后台一键 `POST /api/demo/reset`（二次确认），恢复种子数据
- **数据恢复控制台**：`/data-console` 查看内存数据状态、下载脱敏快照，并输入 `RESTORE_SEED` 恢复全部初始种子；重启服务同样会在首次请求时重新执行 `initSeed()`，当前 demo 不支持快照回灌

## 3.0 平台化能力（P4/P5）

- **多租户**：5 租户（1 真实 + 4 模拟），租户配置/卡产品/佣金规则隔离
- **复式账本**：44 账户（渠道/费用/佣金/卡/商户/企业），append-only 流水，借贷恒等校验（`/api/admin/ledger/verify` 三查全过），余额快照 14 天
- **审批中心**：发卡/KYC 升级/退款/佣金结算/调账 5 类流程，我的待办/我发起的/审批记录，或签+会签对照演示、转交/撤回/超时标记；批准**联动真实业务**（发卡/退款冲正/佣金批量结算/KYC 生效/调账记账）
- **风控规则引擎**：结构化条件（字段×操作符×阈值×且/或）+动作（拦截/冻结/人工审核/标记）+优先级，CRUD+策略版本史，用户风险评分与命中记录；**已接入真实交易链路**（支付/充值前置拦截、入账后冻结联动 frozenBalances）
- **开放平台**：应用/API 密钥/Webhook/API 日志/在线调试（`/api/open/*` 10 个 mock 接口，x-app-key 鉴权）
- **消息中心**：通知模板/发送记录/渠道配置
- **支付编排**：8 适配器（法币×2/USDT/发卡行×2/KYC/FX/结算），渠道路由决策、健康检查、**故障切换**（标宕机自动切备选）、费率比较、交易状态机（幂等键/异步回调/超时补偿/冲正）、三方对账差异一键补单
- **合规中心**：C 端 KYC 案件、企业 KYB+UBO 受益人、AML 筛查（制裁名单 25/PEP 15 模糊匹配）、可疑交易报告 STR、证件到期三档提醒、合规案件、国家政策限制
- **企业服务**：4 中东企业（联动 KYB），成员 5 角色、部门成本中心预算、批量发卡（5311* 卡段）、员工卡限额、超预算消费转审批、月度账单开票+支付记账
- **商户平台**：入驻审核（商户号/APIKey）、借记/贷记/换汇费率+T+0~3、收款订单、退款审核（反向分录）、结算批次（分账拆付）、商户风控、经营报表
- **商户端门户**（/merchant）：免密选商户 → 看板/收款订单/退款申请（后台审核）/结算记录/资料费率
- **BI 数据中心**：DAU/MAU/LTV/CAC/留存/漏斗等 15+ 指标，时间×卡等级×商户×销售多维筛选，自定义报表 CSV 导出（口径自洽：分维度可加和还原总量）
- **运维中心**：生产架构拓扑（demo 现状 vs 预留）、Feature Flag 12 个（含 2 个真实生效点）、内存令牌桶限流（429）、审计日志统一视图、服务监控+错误告警、链路追踪（交易贯穿 6 层）、全量备份导出

## 最终演示动线（PRD 第 10 节）

```
平台创建租户 → 销售创建客户 → 客户 KYC → 运营审核发卡 → 用户充值 → 消费
→ 风控引擎识别 → 积分+多级佣金 → 审批中心处置 → 财务对账 → 商户结算（商户端可查）
→ 企业充值→部门预算→员工消费→审批→账单 → BI 看板汇总
```

## 技术

```
core.js      业务核心（数据+种子+API 路由，node 与 Worker 共用, ESM）
server.js    Node 本地壳（http + 静态）
worker.js    Cloudflare Worker 壳（ASSETS + API）
do.js        Durable Object（单实例内存态）
public/      admin.html 后台 SPA + app.html 用户端 H5 + app-pc.html 电脑版 + merchant.html 商户端（原生 JS 单文件，无框架/CDN）
test/regress.mjs  全量回归（192 项：全部后台/用户端/商户端/开放平台路径 + 冻结挂失/充值消费/审批/风控/企业卡/商户/BI/运维/合规全链路），node test/regress.mjs 一键验证
```

部署：`npx wrangler deploy`（Cloudflare Workers + static assets + **Durable Object** 单实例内存态，多 isolate 强一致，冷启动自动重建种子数据）
