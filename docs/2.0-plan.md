# U-Card 2.0 — Goal & Plan

> 排序原则：**先保证能演示，再补体验，最后补 PRD**

## Goal

把 1.0 的"只读演示系统"升级为**可现场操作的完整演示**：
1. 演示者可现场**新建客户账号、新建客服/销售账号**，数据全链路实时生效
2. 三个 bug 级缺口清零（GMV NaN、时间格式混乱、任务重复领取）
3. 卡片管控（冻结/解冻/挂失）用户端可操作、后端真阻断
4. 演示数据一键重置（现场演示不怕玩脏）
5. 后台/客户端 UI 细节升级（质感、空态、错误兜底）

## Phase 1 — 保证能演示（本轮完成）

| # | 项 | 文件 | 验收 |
|---|---|---|---|
| 1.1 | GMV bug 修复：前端组装 `gmv = topup + consume` | admin.html | 排行榜真实 GMV、完成度正常 %、各级销售正确 |
| 1.2 | 时间统一 `YYYY-MM-DD HH:mm`，统一 `fmtTime` 实现 | admin/app/app-pc/core | 两端同一笔交易时间一致 |

| 1.4 | 任务领取防重复（claimed 状态 + 置灰） | core.js/app*.html | 重复领取返回错误，按钮变"已领取" |
| 1.5 | 卡片管控：`/api/app/card/{freeze,unfreeze,lost}`；充值/消费阻断；后台状态同步+解挂失 | core.js/app*.html/admin.html | 用户端冻结→后台状态同步→消费失败 |
| 1.6 | 新建客户账号（开户+自动发卡）| core.js/admin.html | 新客户立即可在用户端登录 |

## Phase 2 — 补体验（agent 分批并行）

| # | 项 | 要点 |
|---|---|---|
| 2.1 | 后台 UI 质感升级 | 设计变量统一、卡片阴影层次、表格斑马纹/悬浮、空态插画文案、过渡动画 |
| 2.2 | 驾驶舱增强 | GMV/充值/消费总额、活跃用户、卡数、待审 KYC、待发货、待结算佣金、14 天图、榜单点击进详情；NaN→0 兜底 |
| 2.3 | 客户全景详情 | 合并基础资料/CRM 阶段/跟进时间轴/所属销售/关联卡/充值/消费/积分/KYC/佣金贡献/下次跟进 |
| 2.4 | 分销链路页增强 | 每笔交易完整佣金明细表（三级各自金额+状态+来源+关联客户卡）；固定演示流程标注 |
| 2.5 | 用户端 UI 升级 | 手机版+电脑版视觉细节、安全设置/改密码/通知/帮助/客服占位/退出确认 |
| 2.6 | 积分体系增强 | 可用/冻结/即将过期、来源消耗分类、过期与倍率规则说明、任务进度 |
| 2.7 | 全局 UX 兜底 | 加载/无数据/失败/网络/权限模板；杜绝 NaN、undefined、空白页 |

## Phase 3 — 补 PRD（后续批次）

| # | 项 | 要点 |
|---|---|---|
